# 老洪知識點｜Skill 搜尋、建立與架構

本章把 Skill 定義為經驗、規則、參考及工具的可重用封裝。

### LH-SKL-001｜Skill 是可重用工作方法

- 一句話：Skill 的價值不是多一個指令，而是讓已驗證的方法可以被穩定再次使用。
- 課堂原意：老洪把 Skill 放在 Prompt 之後，作為日常工作方法沉澱與自動化的載體。
- 整理與應用：Skill 應固定觸發條件、必要輸入、處理步驟、輸出和驗收。
- 使用時機：一項工作已重複完成，成功模式開始穩定。
- 不適用：問題仍在探索、每次目標都不同，或尚未有一次合格結果。
- 下一步：選一項已成功三次的工作，列出不變步驟和可變輸入。
- 關聯流程：`LH-WF-07`
- Evidence：`DJI_20260830105517_0002_D|00:06:00-00:10:00|Cleaned_Review`

### LH-SKL-002｜主規則與參考資源要分開

- 一句話：核心指令只保留路由和硬規則，詳細知識、範例及工具應按責任拆開。
- 課堂原意：課堂說明 Skill 由主說明、參考及資源構成，並在下一段強調減輕主 Skill 負擔。
- 整理與應用：拆分可以降低規則衝突，也讓更新資料時不必重寫整個 Skill。
- 使用時機：Skill 文件越寫越長、不同場景規則混在一起。
- 不適用：只有單一短流程，拆分反而增加閱讀成本。
- 下一步：把現有說明分成「觸發與流程／參考知識／可執行工具」三類。
- 關聯流程：`LH-WF-08`
- Evidence：`DJI_20260830105517_0002_D|00:06:00-00:10:00|Cleaned_Review`

### LH-SKL-003｜先搜尋，再決定改造或自建

- 一句話：建立 Skill 前應先確認是否已有可借鑑方案，避免重複發明。
- 課堂原意：老洪示範以名稱、GitHub、Skill Hub 及搜尋工具尋找候選。
- 整理與應用：搜尋的目的不是盲目安裝，而是理解已有結構、常見做法和缺口。
- 使用時機：需求屬常見任務，例如研究、寫作、資料處理或文件產出。
- 不適用：涉及高度內部化流程，公開方案不可能包含關鍵業務規則。
- 下一步：用任務、產出物和工具三組關鍵詞搜尋至少三個候選。
- 關聯流程：`LH-WF-06`
- Evidence：`DJI_20260830105517_0002_D|00:10:00-00:15:00|Cleaned_Review`

### LH-SKL-004｜Star 和下載量只是訊號

- 一句話：流行度能協助排序候選，但不能證明它符合你的工作或可以安全使用。
- 課堂原意：課堂把名稱、Star、下載量及真實需求放在同一評估過程。
- 整理與應用：最終判斷要回到觸發是否準確、輸出是否需要、依賴是否可用及規則是否可理解。
- 使用時機：同類 Skill 很多，需要快速縮小範圍。
- 不適用：把熱門程度直接當成品質、安全或適配證明。
- 下一步：為每個候選記錄「適配／依賴／可讀性／維護」四項分數。
- 關聯流程：`LH-WF-06`
- Evidence：`DJI_20260830105517_0002_D|00:10:00-00:15:30|Cleaned_Review`

### LH-SKL-005｜安裝前要讀懂它會做甚麼

- 一句話：候選 Skill 必須先核對觸發、輸入輸出、外部依賴及可能變更，再進入使用。
- 課堂原意：Find Skill 示範的核心是搜索、排名及安裝一條完整路線，而不是只完成下載。
- 整理與應用：團隊應保存來源版本和採用理由，方便日後更新或撤回。
- 使用時機：準備把第三方 Skill 放入日常或團隊環境。
- 不適用：來源、內容或依賴無法檢查的候選。
- 下一步：先讀主說明和所引用的腳本／資源清單，寫一段採用判斷。
- 關聯流程：`LH-WF-06`
- Evidence：`DJI_20260830105517_0002_D|00:14:00-00:20:00|Cleaned_Review`

### LH-SKL-006｜只沉澱已跑通的成功方法

- 一句話：不要把尚未驗證的 Prompt 和錯誤流程封裝成可重用 Skill。
- 課堂原意：老洪明確提出先跑通好結果，再要求 Agent 把方法沉澱下來。
- 整理與應用：封裝前至少保存成功案例、失敗例及驗收標準，否則只會把不確定性自動化。
- 使用時機：準備把個人經驗交給同事或 Agent 重複執行。
- 不適用：研究原型，可暫時記錄假設但不能標成成熟 Skill。
- 下一步：找出兩個不同成功案例和一個失敗案例，提煉共同規則。
- 關聯流程：`LH-WF-07`
- Evidence：`DJI_20260830105517_0002_D|00:20:00-00:24:00|Cleaned_Review`

### LH-SKL-007｜Skill Creator 的難點是思考

- 一句話：建立檔案並不難，真正困難是把隱性經驗說清楚並消除矛盾。
- 課堂原意：小生意分析 Skill 的示範指出，安裝和生成不是最難部分，方法設計才是核心。
- 整理與應用：要把專家的判斷條件、例外、停止點及驗收方式外顯化。
- 使用時機：Agent 能執行步驟，但遇到例外便失去方向。
- 不適用：流程完全機械化，沒有專業判斷或決策分支。
- 下一步：訪談實際執行者，問清楚「甚麼情況下不按標準步驟做」。
- 關聯流程：`LH-WF-07`、`LH-WF-08`
- Evidence：`DJI_20260830105517_0002_D|00:24:00-00:27:43|Cleaned_Review`

### LH-SKL-008｜頂層設計先於規則堆疊

- 一句話：當多個用途混在同一 Skill，應先重畫意圖和路由，不要繼續添加更多規則。
- 課堂原意：第三段開首用 Skill 失敗說明規則混合會令模型難以識別意圖，必須回到頂層設計。
- 整理與應用：先分場景、輸入和交付物，再把共用規則抽出，場景規則分流。
- 使用時機：同一句觸發會走不同路線，或新規則經常破壞舊功能。
- 不適用：單一用途 Skill，只需修正一條明確錯誤規則。
- 下一步：畫出「使用者意圖 → 路由 → 專用流程 → 驗收」四層圖。
- 關聯流程：`LH-WF-08`
- Evidence：`DJI_20260830112259_0003_D|00:00:00-00:08:00|Cleaned_Review`
