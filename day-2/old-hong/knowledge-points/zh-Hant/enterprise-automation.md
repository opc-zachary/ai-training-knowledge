# 老洪知識點｜企業自動化

本章整理自動化形態的演進、隱藏成本及企業入口設計。

### LH-AUTO-001｜自動化經歷三個主要階段

- 一句話：企業 AI 自動化由 Prompt 模板、工作流平台，走向 Agent、Skill 及本地工作台。
- 課堂原意：老洪以三個階段回顧前幾年的提示詞自動化、節點工作流，以及當前 Agent 加 Skill 的方式。
- 整理與應用：選型時應看任務需要的彈性、維護者能力和驗收要求，而不是只追最新名詞。
- 使用時機：企業要理解現有自動化資產是否仍適合。
- 不適用：把演進理解為舊工具全部無效；穩定的固定流程仍可能合適。
- 下一步：把現有自動化逐項標記為模板、工作流或 Agent 系統。
- 關聯流程：`LH-WF-11`

### LH-AUTO-002｜工具會過時，原理比介面持久

- 一句話：學習應集中在問題拆解、資料流、判斷和驗收，而不是押注某一個平台。
- 課堂原意：老洪回顧多個曾經流行的平台，指出工具變化很快，而底層理解更持久。
- 整理與應用：文件先描述業務流程和輸入輸出，再把當前工具作為可替換實現。
- 使用時機：團隊擔心新工具出現後，之前投入全部報廢。
- 不適用：必要的工具操作仍需學習，只是不應成為唯一資產。
- 下一步：把一條自動化文件中的平台名稱抽走，檢查流程是否仍可理解。
- 關聯流程：`LH-WF-11`
- Evidence：`DJI_20260830114141_0004_D|00:01:30-00:04:30|Cleaned_Review`

### LH-AUTO-003｜節點少不代表實作簡單

- 一句話：流程圖上的五個節點，背後可能包含帳號、接口、參數和錯誤處理的巨大成本。
- 課堂原意：老洪以一個看似只有少量節點的採集工作流作反面教材，說明配置過程仍非常複雜。
- 整理與應用：估算自動化時要計算節點背後的依賴、維護及故障恢復，不只數方框。
- 使用時機：供應商或內部提案以「只有幾步」形容方案很簡單。
- 不適用：經過長期驗證且依賴已標準化的固定流程。
- 下一步：為每個節點列出身份、輸入、輸出、依賴、失敗及負責人。
- 關聯流程：`LH-WF-11`

### LH-AUTO-004｜隱藏配置成本會吞噬自動化收益

- 一句話：如果每次故障都需要重新申請、配置或理解大量參數，自動化可能比人工更難維護。
- 課堂原意：課堂描述花大量時間處理接口、帳號、參數和反覆報錯，最後仍未跑通的經驗。
- 整理與應用：方案評估要加入首次建立時間、每月維護時間、故障頻率和替代路徑。
- 使用時機：PoC 看似成功，但只有原開發者能處理問題。
- 不適用：高價值流程即使維護成本高，仍可能值得保留。
- 下一步：為現有流程計算總持有成本，而非只看首次製作費。
- 關聯流程：`LH-WF-11`
- Evidence：`DJI_20260830114141_0004_D|00:04:30-00:07:00|Cleaned_Review`

### LH-AUTO-005｜教學者視角與使用者視角可能錯位

- 一句話：程序員認為簡單的配置，對業務使用者可能充滿陌生概念和失敗點。
- 課堂原意：老洪指出網上教學常以程序員視角說明，非技術使用者甚至無法理解名詞。
- 整理與應用：企業入口要用業務語言呈現任務、輸入和結果，把技術細節留在維護層。
- 使用時機：培訓完成後，員工仍不敢或不懂使用流程。
- 不適用：工具只供專業工程團隊內部使用。
- 下一步：請一位非技術同事只看操作入口完成一次任務，記錄所有卡點。
- 關聯流程：`LH-WF-09`、`LH-WF-11`
- Evidence：`DJI_20260830114141_0004_D|00:05:00-00:07:30|Cleaned_Review`

### LH-AUTO-006｜企業入口應是 Skill 或看板

- 一句話：員工應從清楚任務入口使用已設計能力，而不是每個人重新搭建底層流程。
- 課堂原意：老洪建議把資料、數據及小工具放入 Skill，或為企業建立看板供員工使用。
- 整理與應用：入口負責收集必要輸入、限制選項、顯示狀態及輸出驗收。
- 使用時機：企業希望多人使用同一 AI 能力，且要減少個人操作差異。
- 不適用：流程仍在快速探索，過早固定入口會阻礙試驗。
- 下一步：把一項高頻任務改成不超過五個輸入欄位的業務入口草圖。
- 關聯流程：`LH-WF-09`、`LH-WF-11`
- Evidence：`DJI_20260830114141_0004_D|00:06:00-00:08:30|Cleaned_Review`

### LH-AUTO-007｜不要要求每位員工掌握底層技術

- 一句話：企業擴散靠的是設計良好的使用方式，而不是把所有員工訓練成工程師。
- 課堂原意：老洪強調不能指望每個員工都理解複雜 Prompt 或配置，只需能使用設計好的入口。
- 整理與應用：建立者負責複雜度，使用者負責提供業務輸入、判斷結果和回報例外。
- 使用時機：AI 推廣被大量工具培訓拖慢，員工採用率低。
- 不適用：核心 AI 團隊本身需要理解並維護底層系統。
- 下一步：把培訓拆成「使用者操作」和「維護者診斷」兩條路線。
- 關聯流程：`LH-WF-09`、`LH-WF-12`
- Evidence：`DJI_20260830114141_0004_D|00:06:30-00:08:30|Cleaned_Review`

### LH-AUTO-008｜自動化目標是業務改善

- 一句話：採用 AI 的理由必須回到效率、品質、速度或決策改善，而不是為了顯示用了 AI。
- 課堂原意：老洪指出只買工具或模型而沒有打通業務流程，反而可能增加阻礙。
- 整理與應用：每個方案先定義現況基線和可見業務成果，再決定是否需要 AI。
- 使用時機：管理層先指定工具，團隊卻說不清要改善哪個指標。
- 不適用：純學習實驗可以不立即承擔商業回報，但仍要標明實驗目的。
- 下一步：用一句話寫出「若成功，哪個角色的哪項結果會改善多少」。
- 關聯流程：`LH-WF-11`、`LH-WF-12`
- Evidence：`DJI_20260830114141_0004_D|00:07:00-00:10:00|Cleaned_Review`
