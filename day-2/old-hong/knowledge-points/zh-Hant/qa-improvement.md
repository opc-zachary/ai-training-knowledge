# 老洪知識點｜測試、驗收與持續改進

本章把課堂中分散的測試、觀察、復盤及交付原則整理成品質閉環。

### LH-QA-001｜先確認任務，再討論工具

- 一句話：如果問題本身沒有定義清楚，更強的模型和更多工具也只會更快產出錯誤方向。
- 課堂原意：Prompt 方法由「到底要解決甚麼任務」開始，企業自動化亦回到業務改善。
- 整理與應用：驗收的第一項不是格式，而是成品是否解決原本決策或工作問題。
- 使用時機：團隊討論集中在模型、平台或功能名稱。
- 不適用：已有明確任務，只需進行工具相容性測試。
- 下一步：在任務文件頂部加入一條可由業務負責人判斷成敗的問題。
- 關聯流程：`LH-WF-01`、`LH-WF-11`

### LH-QA-002｜測試要隔離隱藏 Context

- 一句話：只有在乾淨環境仍能成功，方法才真正具備交付和重用價值。
- 課堂原意：老洪用新窗口執行第一版 Prompt，避免舊對話提供未寫出的背景。
- 整理與應用：正式測試輸入應等同下一位使用者真正會收到的資料。
- 使用時機：把個人方法交給團隊或封裝成 Skill 前。
- 不適用：方法明確設計成依賴某個長期項目 Context。
- 下一步：移除所有非正式歷史，重跑一次並標記新增的必要輸入。
- 關聯流程：`LH-WF-02`
- Evidence：`DJI_20260830102734_0001_D|00:18:00-00:22:00|Cleaned_Review`

### LH-QA-003｜至少用兩個不同案例驗證

- 一句話：單一成功只能證明案例成功，兩個不同案例才能開始證明方法可重用。
- 課堂原意：課堂要求用另一品類測試 Prompt，並在 Skill 指南中形成多案例驗收觀點。
- 整理與應用：第二案例應改變行業資料或使用者輸入，但保留同一任務結構。
- 使用時機：準備把流程標成模板、Playbook 或 Skill。
- 不適用：只服務唯一個案且不計劃重用。
- 下一步：挑選一個相似案例和一個邊界案例，記錄通過及失敗條件。
- 關聯流程：`LH-WF-02`、`LH-WF-07`
- Evidence：`DJI_20260830102734_0001_D|00:18:00-00:22:00|Cleaned_Review`

### LH-QA-004｜一次只改一類主要問題

- 一句話：同時改目標、流程、格式和資料，會令團隊無法知道哪項修改真正有效。
- 課堂原意：Prompt 排錯被拆成四類，為逐層定位和修復提供基礎。
- 整理與應用：保留基準輸入，先修最主要失敗層，再比較結果。
- 使用時機：Prompt 正在反覆改動，品質卻沒有可解釋進步。
- 不適用：規格包含明顯互相矛盾要求，應先整體修正。
- 下一步：為下一輪測試寫下唯一改動、預期影響及比較指標。
- 關聯流程：`LH-WF-03`、`LH-WF-05`
- Evidence：`DJI_20260830105517_0002_D|00:02:00-00:06:00|Cleaned_Review`

### LH-QA-005｜失敗要能歸因到明確層次

- 一句話：可改善的系統必須知道失敗屬 Prompt、規則、工具、輸入還是 Context。
- 課堂原意：老洪以 Prompt 排錯、Skill 結構及工具執行問題說明不同失敗來源。
- 整理與應用：每次失敗記錄主要原因、證據、修復者及是否需要更新共用規則。
- 使用時機：同一流程由多人維護，故障經常重複出現。
- 不適用：尚未有足夠證據，只能標記為未知並保留調查。
- 下一步：建立五類失敗標籤並回填最近五次問題。
- 關聯流程：`LH-WF-05`、`LH-WF-07`
- Evidence：`DJI_20260830105517_0002_D|00:04:00-00:10:00|Cleaned_Review`

### LH-QA-006｜數據事實與原因假設分開

- 一句話：報表告訴你發生了甚麼，復盤假設才嘗試解釋為甚麼。
- 課堂原意：老洪在月度工作台強調要理解數據好與差的原因，而不只看到數字。
- 整理與應用：每個原因都要寫驗證方式，避免把直覺直接升級成規則。
- 使用時機：內容、營銷、銷售或營運月度復盤。
- 不適用：資料來源或指標定義不可靠，應先修復資料品質。
- 下一步：為一個異常數據寫三個候選原因及下一輪驗證方法。
- 關聯流程：`LH-WF-10`
- Evidence：`DJI_20260830112259_0003_D|00:12:00-00:16:30|Cleaned_Review`

### LH-QA-007｜復盤結果要回寫下一輪規則

- 一句話：如果檢討只產生報告而沒有改變流程，它不會形成自主改善。
- 課堂原意：工作台由數據回流進入自主復盤，再影響下一輪內容和工作方式。
- 整理與應用：每次只晉升有證據、可重複、影響明確的學習，並記錄版本。
- 使用時機：同類任務持續運行，需要逐月提升品質或效率。
- 不適用：一次性項目，學習可記錄但未必需要修改共用系統。
- 下一步：從本月復盤選一條可測試規則，加入下月流程並設定撤回條件。
- 關聯流程：`LH-WF-03`、`LH-WF-10`
- Evidence：`DJI_20260830112259_0003_D|00:14:00-00:17:00|Cleaned_Review`

### LH-QA-008｜完成不只等於系統建好

- 一句話：企業 AI 的完成證據還包括使用者採用、可見成果、交接和持續運作。
- 課堂原意：FDE 應對採用及結果負責，並經歷試點、上線、交接、復用和持續更新。
- 整理與應用：把技術驗收、業務驗收、採用驗收及維護驗收分開。
- 使用時機：PoC 已能運行，但企業尚未真正把它用進日常工作。
- 不適用：純研究原型可只交付技術證據，但不可稱為企業落地完成。
- 下一步：為試點補上使用頻率、節省時間、錯誤率和交接通過四項指標。
- 關聯流程：`LH-WF-12`
