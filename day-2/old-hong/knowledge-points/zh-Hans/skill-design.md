# 老洪知识点｜Skill 搜寻、建立与架构

本章把 Skill 定义为经验、规则、参考及工具的可重用封装。

### LH-SKL-001｜Skill 是可重用工作方法

- 一句话：Skill 的价值不是多一个指令，而是让已验证的方法可以被稳定再次使用。
- 课堂原意：老洪把 Skill 放在 Prompt 之后，作为日常工作方法沉淀与自动化的载体。
- 整理与应用：Skill 应固定触发条件、必要输入、处理步骤、输出和验收。
- 使用时机：一项工作已重复完成，成功模式开始稳定。
- 不适用：问题仍在探索、每次目标都不同，或尚未有一次合格结果。
- 下一步：选一项已成功三次的工作，列出不变步骤和可变输入。
- 关联流程：`LH-WF-07`

### LH-SKL-002｜主规则与参考资源要分开

- 一句话：核心指令只保留路由和硬规则，详细知识、范例及工具应按责任拆开。
- 课堂原意：课堂说明 Skill 由主说明、参考及资源构成，并在下一段强调减轻主 Skill 负担。
- 整理与应用：拆分可以降低规则冲突，也让更新资料时不必重写整个 Skill。
- 使用时机：Skill 文件越写越长、不同场景规则混在一起。
- 不适用：只有单一短流程，拆分反而增加阅读成本。
- 下一步：把现有说明分成「触发与流程／参考知识／可执行工具」三类。
- 关联流程：`LH-WF-08`
- Evidence：`DJI_20260830105517_0002_D|00:06:00-00:10:00|Cleaned_Review`

### LH-SKL-003｜先搜寻，再决定改造或自建

- 一句话：建立 Skill 前应先确认是否已有可借鉴方案，避免重复发明。
- 课堂原意：老洪示范以名称、GitHub、Skill Hub 及搜寻工具寻找候选。
- 整理与应用：搜寻的目的不是盲目安装，而是理解已有结构、常见做法和缺口。
- 使用时机：需求属常见任务，例如研究、写作、资料处理或文件产出。
- 不适用：涉及高度内部化流程，公开方案不可能包含关键业务规则。
- 下一步：用任务、产出物和工具三组关键词搜寻至少三个候选。
- 关联流程：`LH-WF-06`
- Evidence：`DJI_20260830105517_0002_D|00:10:00-00:15:00|Cleaned_Review`

### LH-SKL-004｜Star 和下载量只是讯号

- 一句话：流行度能协助排序候选，但不能证明它符合你的工作或可以安全使用。
- 课堂原意：课堂把名称、Star、下载量及真实需求放在同一评估过程。
- 整理与应用：最终判断要回到触发是否准确、输出是否需要、依赖是否可用及规则是否可理解。
- 使用时机：同类 Skill 很多，需要快速缩小范围。
- 不适用：把热门程度直接当成品质、安全或适配证明。
- 下一步：为每个候选记录「适配／依赖／可读性／维护」四项分数。
- 关联流程：`LH-WF-06`
- Evidence：`DJI_20260830105517_0002_D|00:10:00-00:15:30|Cleaned_Review`

### LH-SKL-005｜安装前要读懂它会做什么

- 一句话：候选 Skill 必须先核对触发、输入输出、外部依赖及可能变更，再进入使用。
- 课堂原意：Find Skill 示范的核心是搜索、排名及安装一条完整路线，而不是只完成下载。
- 整理与应用：团队应保存来源版本和采用理由，方便日后更新或撤回。
- 使用时机：准备把第三方 Skill 放入日常或团队环境。
- 不适用：来源、内容或依赖无法检查的候选。
- 下一步：先读主说明和所引用的脚本／资源清单，写一段采用判断。
- 关联流程：`LH-WF-06`
- Evidence：`DJI_20260830105517_0002_D|00:14:00-00:20:00|Cleaned_Review`

### LH-SKL-006｜只沉淀已跑通的成功方法

- 一句话：不要把尚未验证的 Prompt 和错误流程封装成可重用 Skill。
- 课堂原意：老洪明确提出先跑通好结果，再要求 Agent 把方法沉淀下来。
- 整理与应用：封装前至少保存成功案例、失败例及验收标准，否则只会把不确定性自动化。
- 使用时机：准备把个人经验交给同事或 Agent 重复执行。
- 不适用：研究原型，可暂时记录假设但不能标成成熟 Skill。
- 下一步：找出两个不同成功案例和一个失败案例，提炼共同规则。
- 关联流程：`LH-WF-07`
- Evidence：`DJI_20260830105517_0002_D|00:20:00-00:24:00|Cleaned_Review`

### LH-SKL-007｜Skill Creator 的难点是思考

- 一句话：建立档案并不难，真正困难是把隐性经验说清楚并消除矛盾。
- 课堂原意：小生意分析 Skill 的示范指出，安装和生成不是最难部分，方法设计才是核心。
- 整理与应用：要把专家的判断条件、例外、停止点及验收方式外显化。
- 使用时机：Agent 能执行步骤，但遇到例外便失去方向。
- 不适用：流程完全机械化，没有专业判断或决策分支。
- 下一步：访谈实际执行者，问清楚「什么情况下不按标准步骤做」。
- 关联流程：`LH-WF-07`、`LH-WF-08`
- Evidence：`DJI_20260830105517_0002_D|00:24:00-00:27:43|Cleaned_Review`

### LH-SKL-008｜顶层设计先于规则堆叠

- 一句话：当多个用途混在同一 Skill，应先重画意图和路由，不要继续添加更多规则。
- 课堂原意：第三段开首用 Skill 失败说明规则混合会令模型难以识别意图，必须回到顶层设计。
- 整理与应用：先分场景、输入和交付物，再把共用规则抽出，场景规则分流。
- 使用时机：同一句触发会走不同路线，或新规则经常破坏旧功能。
- 不适用：单一用途 Skill，只需修正一条明确错误规则。
- 下一步：画出「使用者意图 → 路由 → 专用流程 → 验收」四层图。
- 关联流程：`LH-WF-08`
