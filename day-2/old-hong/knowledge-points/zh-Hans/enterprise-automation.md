# 老洪知识点｜企业自动化

本章整理自动化形态的演进、隐藏成本及企业入口设计。

### LH-AUTO-001｜自动化经历三个主要阶段

- 一句话：企业 AI 自动化由 Prompt 模板、工作流平台，走向 Agent、Skill 及本地工作台。
- 课堂原意：老洪以三个阶段回顾前几年的提示词自动化、节点工作流，以及当前 Agent 加 Skill 的方式。
- 整理与应用：选型时应看任务需要的弹性、维护者能力和验收要求，而不是只追最新名词。
- 使用时机：企业要理解现有自动化资产是否仍适合。
- 不适用：把演进理解为旧工具全部无效；稳定的固定流程仍可能合适。
- 下一步：把现有自动化逐项标记为模板、工作流或 Agent 系统。

### LH-AUTO-002｜工具会过时，原理比介面持久

- 一句话：学习应集中在问题拆解、资料流、判断和验收，而不是押注某一个平台。
- 课堂原意：老洪回顾多个曾经流行的平台，指出工具变化很快，而底层理解更持久。
- 整理与应用：文件先描述业务流程和输入输出，再把当前工具作为可替换实现。
- 使用时机：团队担心新工具出现后，之前投入全部报废。
- 不适用：必要的工具操作仍需学习，只是不应成为唯一资产。
- 下一步：把一条自动化文件中的平台名称抽走，检查流程是否仍可理解。
- 关联流程：`LH-WF-11`

### LH-AUTO-003｜节点少不代表实作简单

- 一句话：流程图上的五个节点，背后可能包含帐号、接口、参数和错误处理的巨大成本。
- 课堂原意：老洪以一个看似只有少量节点的采集工作流作反面教材，说明配置过程仍非常复杂。
- 整理与应用：估算自动化时要计算节点背后的依赖、维护及故障恢复，不只数方框。
- 使用时机：供应商或内部提案以「只有几步」形容方案很简单。
- 不适用：经过长期验证且依赖已标准化的固定流程。
- 下一步：为每个节点列出身份、输入、输出、依赖、失败及负责人。
- 关联流程：`LH-WF-11`

### LH-AUTO-004｜隐藏配置成本会吞噬自动化收益

- 一句话：如果每次故障都需要重新申请、配置或理解大量参数，自动化可能比人工更难维护。
- 课堂原意：课堂描述花大量时间处理接口、帐号、参数和反覆报错，最后仍未跑通的经验。
- 整理与应用：方案评估要加入首次建立时间、每月维护时间、故障频率和替代路径。
- 使用时机：PoC 看似成功，但只有原开发者能处理问题。
- 不适用：高价值流程即使维护成本高，仍可能值得保留。
- 下一步：为现有流程计算总持有成本，而非只看首次制作费。
- 关联流程：`LH-WF-11`

### LH-AUTO-005｜教学者视角与使用者视角可能错位

- 一句话：程序员认为简单的配置，对业务使用者可能充满陌生概念和失败点。
- 课堂原意：老洪指出网上教学常以程序员视角说明，非技术使用者甚至无法理解名词。
- 整理与应用：企业入口要用业务语言呈现任务、输入和结果，把技术细节留在维护层。
- 使用时机：培训完成后，员工仍不敢或不懂使用流程。
- 不适用：工具只供专业工程团队内部使用。
- 下一步：请一位非技术同事只看操作入口完成一次任务，记录所有卡点。
- 关联流程：`LH-WF-09`、`LH-WF-11`

### LH-AUTO-006｜企业入口应是 Skill 或看板

- 一句话：员工应从清楚任务入口使用已设计能力，而不是每个人重新搭建底层流程。
- 课堂原意：老洪建议把资料、数据及小工具放入 Skill，或为企业建立看板供员工使用。
- 整理与应用：入口负责收集必要输入、限制选项、显示状态及输出验收。
- 使用时机：企业希望多人使用同一 AI 能力，且要减少个人操作差异。
- 不适用：流程仍在快速探索，过早固定入口会阻碍试验。
- 下一步：把一项高频任务改成不超过五个输入栏位的业务入口草图。
- 关联流程：`LH-WF-09`、`LH-WF-11`

### LH-AUTO-007｜不要要求每位员工掌握底层技术

- 一句话：企业扩散靠的是设计良好的使用方式，而不是把所有员工训练成工程师。
- 课堂原意：老洪强调不能指望每个员工都理解复杂 Prompt 或配置，只需能使用设计好的入口。
- 整理与应用：建立者负责复杂度，使用者负责提供业务输入、判断结果和回报例外。
- 使用时机：AI 推广被大量工具培训拖慢，员工采用率低。
- 不适用：核心 AI 团队本身需要理解并维护底层系统。
- 下一步：把培训拆成「使用者操作」和「维护者诊断」两条路线。
- 关联流程：`LH-WF-09`、`LH-WF-12`
- Evidence：`DJI_20260830114141_0004_D|00:06:30-00:08:30|Cleaned_Review`

### LH-AUTO-008｜自动化目标是业务改善

- 一句话：采用 AI 的理由必须回到效率、品质、速度或决策改善，而不是为了显示用了 AI。
- 课堂原意：老洪指出只买工具或模型而没有打通业务流程，反而可能增加阻碍。
- 整理与应用：每个方案先定义现况基线和可见业务成果，再决定是否需要 AI。
- 使用时机：管理层先指定工具，团队却说不清要改善哪个指标。
- 不适用：纯学习实验可以不立即承担商业回报，但仍要标明实验目的。
- 下一步：用一句话写出「若成功，哪个角色的哪项结果会改善多少」。
- 关联流程：`LH-WF-11`、`LH-WF-12`
