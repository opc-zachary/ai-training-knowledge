# 老洪知识点｜测试、验收与持续改进

本章把课堂中分散的测试、观察、复盘及交付原则整理成品质闭环。

### LH-QA-001｜先确认任务，再讨论工具

- 一句话：如果问题本身没有定义清楚，更强的模型和更多工具也只会更快产出错误方向。
- 课堂原意：Prompt 方法由「到底要解决什么任务」开始，企业自动化亦回到业务改善。
- 整理与应用：验收的第一项不是格式，而是成品是否解决原本决策或工作问题。
- 使用时机：团队讨论集中在模型、平台或功能名称。
- 不适用：已有明确任务，只需进行工具相容性测试。
- 下一步：在任务文件顶部加入一条可由业务负责人判断成败的问题。
- 关联流程：`LH-WF-01`、`LH-WF-11`

### LH-QA-002｜测试要隔离隐藏 Context

- 一句话：只有在干净环境仍能成功，方法才真正具备交付和重用价值。
- 课堂原意：老洪用新窗口执行第一版 Prompt，避免旧对话提供未写出的背景。
- 整理与应用：正式测试输入应等同下一位使用者真正会收到的资料。
- 使用时机：把个人方法交给团队或封装成 Skill 前。
- 不适用：方法明确设计成依赖某个长期项目 Context。
- 下一步：移除所有非正式历史，重跑一次并标记新增的必要输入。
- 关联流程：`LH-WF-02`

### LH-QA-003｜至少用两个不同案例验证

- 一句话：单一成功只能证明案例成功，两个不同案例才能开始证明方法可重用。
- 课堂原意：课堂要求用另一品类测试 Prompt，并在 Skill 指南中形成多案例验收观点。
- 整理与应用：第二案例应改变行业资料或使用者输入，但保留同一任务结构。
- 使用时机：准备把流程标成模板、Playbook 或 Skill。
- 不适用：只服务唯一个案且不计划重用。
- 下一步：挑选一个相似案例和一个边界案例，记录通过及失败条件。
- 关联流程：`LH-WF-02`、`LH-WF-07`
- Evidence：`DJI_20260830102734_0001_D|00:18:00-00:22:00|Cleaned_Review`

### LH-QA-004｜一次只改一类主要问题

- 一句话：同时改目标、流程、格式和资料，会令团队无法知道哪项修改真正有效。
- 课堂原意：Prompt 排错被拆成四类，为逐层定位和修复提供基础。
- 整理与应用：保留基准输入，先修最主要失败层，再比较结果。
- 使用时机：Prompt 正在反覆改动，品质却没有可解释进步。
- 不适用：规格包含明显互相矛盾要求，应先整体修正。
- 下一步：为下一轮测试写下唯一改动、预期影响及比较指标。
- 关联流程：`LH-WF-03`、`LH-WF-05`
- Evidence：`DJI_20260830105517_0002_D|00:02:00-00:06:00|Cleaned_Review`

### LH-QA-005｜失败要能归因到明确层次

- 一句话：可改善的系统必须知道失败属 Prompt、规则、工具、输入还是 Context。
- 课堂原意：老洪以 Prompt 排错、Skill 结构及工具执行问题说明不同失败来源。
- 整理与应用：每次失败记录主要原因、证据、修复者及是否需要更新共用规则。
- 使用时机：同一流程由多人维护，故障经常重复出现。
- 不适用：尚未有足够证据，只能标记为未知并保留调查。
- 下一步：建立五类失败标签并回填最近五次问题。
- 关联流程：`LH-WF-05`、`LH-WF-07`
- Evidence：`DJI_20260830105517_0002_D|00:04:00-00:10:00|Cleaned_Review`

### LH-QA-006｜数据事实与原因假设分开

- 一句话：报表告诉你发生了什么，复盘假设才尝试解释为什么。
- 课堂原意：老洪在月度工作台强调要理解数据好与差的原因，而不只看到数字。
- 整理与应用：每个原因都要写验证方式，避免把直觉直接升级成规则。
- 使用时机：内容、营销、销售或营运月度复盘。
- 不适用：资料来源或指标定义不可靠，应先修复资料品质。
- 下一步：为一个异常数据写三个候选原因及下一轮验证方法。
- 关联流程：`LH-WF-10`

### LH-QA-007｜复盘结果要回写下一轮规则

- 一句话：如果检讨只产生报告而没有改变流程，它不会形成自主改善。
- 课堂原意：工作台由数据回流进入自主复盘，再影响下一轮内容和工作方式。
- 整理与应用：每次只晋升有证据、可重复、影响明确的学习，并记录版本。
- 使用时机：同类任务持续运行，需要逐月提升品质或效率。
- 不适用：一次性项目，学习可记录但未必需要修改共用系统。
- 下一步：从本月复盘选一条可测试规则，加入下月流程并设定撤回条件。
- 关联流程：`LH-WF-03`、`LH-WF-10`

### LH-QA-008｜完成不只等于系统建好

- 一句话：企业 AI 的完成证据还包括使用者采用、可见成果、交接和持续运作。
- 课堂原意：FDE 应对采用及结果负责，并经历试点、上线、交接、复用和持续更新。
- 整理与应用：把技术验收、业务验收、采用验收及维护验收分开。
- 使用时机：PoC 已能运行，但企业尚未真正把它用进日常工作。
- 不适用：纯研究原型可只交付技术证据，但不可称为企业落地完成。
- 下一步：为试点补上使用频率、节省时间、错误率和交接通过四项指标。
- 关联流程：`LH-WF-12`
