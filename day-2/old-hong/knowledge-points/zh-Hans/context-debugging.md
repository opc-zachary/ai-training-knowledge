# 老洪知识点｜Context 与 Prompt 排错

本章整理长任务的资讯管理，以及输出偏差时的诊断顺序。

### LH-CTX-001｜Context Window 是有限工作记忆

- 一句话：同一窗口承载的历史越多，可供当前任务使用的有效空间便越少。
- 课堂原意：老洪指出长对话会令早期细节遗失，复杂任务需要拆分或开新窗口。
- 整理与应用：Context 应视为任务资源；不是资料放得越多越好，而是保留与当前判断有关的内容。
- 使用时机：对话很长、要求很多、模型开始忘记早期约束。
- 不适用：短小且输入明确的单轮任务。
- 下一步：列出当前任务真正需要保留的目标、来源、规则和状态。
- 关联流程：`LH-WF-04`
- Evidence：`DJI_20260830102734_0001_D|00:22:00-00:27:00|Cleaned_Review`

### LH-CTX-002｜自动压缩可能牺牲细节

- 一句话：系统为延续长对话而压缩历史时，细节、例外和先后关系可能被弱化。
- 课堂原意：第二段开首延续 Context Window，说明过长内容会导致资讯损失。
- 整理与应用：重要限制要写入明确的任务摘要或来源文件，不可只依赖对话记忆。
- 使用时机：长期项目、跨日工作、多个文件或多人规则共同存在。
- 不适用：资料可随时由单一权威文件重新载入。
- 下一步：把不可遗失的五项规则整理成「重新开始也能使用」的 Context Brief。
- 关联流程：`LH-WF-04`
- Evidence：`DJI_20260830105517_0002_D|00:00:00-00:02:00|Cleaned_Review`

### LH-CTX-003｜新窗口是隔离实验环境

- 一句话：测试 Prompt 时要在干净窗口执行，避免旧对话暗中提供答案。
- 课堂原意：老洪示范把第一版提示词放到新任务，测试它是否单独成立。
- 整理与应用：旧 Context 可协助设计 Prompt，但验收必须在没有隐藏背景的环境进行。
- 使用时机：准备交付 Prompt、Skill 或标准流程给其他人。
- 不适用：刻意需要延续个人偏好和项目历史的同一工作线。
- 下一步：把 Prompt 复制到新窗口，只提供正式输入，记录是否仍能产出合格结果。
- 关联流程：`LH-WF-02`
- Evidence：`DJI_20260830102734_0001_D|00:18:00-00:22:00|Cleaned_Review`

### LH-CTX-004｜复杂任务要按成果切分

- 一句话：切分任务的单位应是可验收成果，而不是任意把长文字分成几段。
- 课堂原意：课堂建议复杂内容分块处理，避免单一 Context 承载全部工作。
- 整理与应用：每一段要有输入、产出、完成条件及交接摘要，下一段才能安全延续。
- 使用时机：研究、内容生产、资料分析或跨多阶段的 Agent 任务。
- 不适用：步骤高度耦合，拆开后会失去必要的即时状态。
- 下一步：把一个大任务改写为三个各自可验收的交付物。
- 关联流程：`LH-WF-04`
- Evidence：`DJI_20260830102734_0001_D|00:24:00-00:27:42|Cleaned_Review`

### LH-CTX-005｜结构化格式减少理解歧义

- 一句话：标题、栏位、清单和输出格式能把自然语言要求转成较稳定的操作规格。
- 课堂原意：老洪在 Prompt 格式与排错部分强调结构化表达对控制输出的作用。
- 整理与应用：结构不是为了让 Prompt 看起来复杂，而是让每项要求可以逐一检查。
- 使用时机：要求包含多个对象、步骤、限制或格式。
- 不适用：简短探索对话，过早固定格式会限制发现空间。
- 下一步：把一段散文式要求改成「目标／资料／步骤／输出／验收」。
- 关联流程：`LH-WF-05`
- Evidence：`DJI_20260830105517_0002_D|00:02:00-00:06:00|Cleaned_Review`

### LH-CTX-006｜Prompt 四层排错

- 一句话：答非所问时，依序检查目标、流程、格式及背景资料，不要只叫模型「再做好一点」。
- 课堂原意：课堂把 Prompt 问题拆成目标、流程、格式、背景四类。
- 整理与应用：四层对应四种修复方式：重定义成果、补方法、明确结构、补充来源。
- 使用时机：结果不合格，但不知道问题来自哪里。
- 不适用：工具故障、权限不足或输入档案损坏等非 Prompt 问题。
- 下一步：只选一层做最小修改，再重跑同一测试案例。
- 关联流程：`LH-WF-05`
- Evidence：`DJI_20260830105517_0002_D|00:02:30-00:06:00|Cleaned_Review`

### LH-CTX-007｜重置 Context 前先留下交接摘要

- 一句话：开新窗口不是把一切忘掉，而是只带走已确认的目标、资料、决定和未完成项。
- 课堂原意：Context 管理的目的，是避免旧内容污染，同时保留任务需要的背景。
- 整理与应用：交接摘要应区分事实、决定、假设、限制及下一步，避免把推测变成真相。
- 使用时机：任务跨窗口、跨人或跨 Agent 延续。
- 不适用：新任务与旧任务完全无关，没有任何状态需要保留。
- 下一步：用五个栏位制作一页 Handoff，再在新窗口以它作唯一历史输入。
- 关联流程：`LH-WF-04`
- Evidence：`DJI_20260830105517_0002_D|00:00:00-00:02:00|Cleaned_Review`

### LH-CTX-008｜先分辨 Prompt 问题与系统问题

- 一句话：输出失败不一定是 Prompt 写得差，也可能是资料、工具、能力或 Context 不足。
- 课堂原意：老洪把排错与 Skill、资料及工具结合，提醒学员不要把所有失败都归因于一句指令。
- 整理与应用：先定位失败层，才能选择重写 Prompt、补资料、换工具或拆任务。
- 使用时机：同一 Prompt 有时成功、有时失败，或模型没有实际执行能力。
- 不适用：已明确看到要求本身互相矛盾，应先修正规格。
- 下一步：为一次失败标记 `Prompt／Context／Input／Tool／Rule` 其中一个主要原因。
- 关联流程：`LH-WF-05`、`LH-WF-07`
- Evidence：`DJI_20260830105517_0002_D|00:04:00-00:08:00|Cleaned_Review`
