# 教學模組 02｜Context、Prompt 排錯與 Skill 入門

建議時長：90 分鐘

## 對象與先備知識

- 對象：需要處理長任務、排查 AI 輸出或開始使用 Skill 的團隊。
- 先備：能提供一個曾經答非所問的 Prompt 案例。

## 學習成果

1. 判斷 Context 超載及隱藏背景污染。
2. 用四層排錯定位主要根因。
3. 建立可在新窗口使用的交接摘要。
4. 搜尋和評估現成 Skill，而不只看人氣。

## 分鐘級流程

| 時間 | 教學活動 | 講師提示 | 學員產出 |
|---|---|---|---|
| 00–10 | 長對話失準診斷 | 比較遺忘、混線及壓縮症狀 | 症狀分類 |
| 10–22 | Context Brief | 區分事實、決定、假設、限制 | 一頁交接摘要 |
| 22–38 | 四層排錯講解 | 目標、流程、格式、背景逐層檢查 | 四層診斷表 |
| 38–52 | 失敗案例修復 | 只允許修改一個主要層 | 修訂 Prompt |
| 52–62 | Skill 定義 | 說明可重用方法與一般 Prompt 的差別 | 可封裝候選 |
| 62–76 | 搜尋示範 | 任務、產出、工具三組關鍵詞 | 三個候選 |
| 76–86 | 候選評估 | 適配、依賴、可讀性、維護 | 比較表 |
| 86–90 | Exit Ticket | 問「這次失敗真正屬哪一層？」 | 根因一句話 |

## 講師示範

- 把一段過長 Context 壓縮成六欄交接摘要。
- 對一個答非所問案例逐層排錯，不以「再專業一點」作修復。
- 查看候選 Skill 的實際規則和依賴，再與介紹頁比較。

## 學員練習

1. 使用自己的失敗 Prompt 填四層診斷。
2. 建立最小修訂並在固定案例重跑。
3. 為一項工作搜尋三個 Skill 候選。
4. 作出採用、改造、借鑑或自建決定。

## 檢查問題

- 哪些資訊是事實，哪些只是過去對話推測？
- 修改的是目標、流程、格式還是背景？
- 候選 Skill 會依賴甚麼工具或外部資料？
- 如果候選很熱門但不符合交付物，應如何處理？

## 課後作業

提交一份 Context Brief、一份 Prompt 排錯記錄及一份三候選 Skill 評估表。

## 評分量規

| 維度 | 未通過 | 基本通過 | 熟練 |
|---|---|---|---|
| Context | 複製全部歷史 | 有最小摘要 | 事實、決定、假設清楚分開 |
| 排錯 | 同時重寫所有內容 | 定位主要層 | 可重現並證明修訂有效 |
| 搜尋 | 只找一個候選 | 比較三個候選 | 實際閱讀規則與依賴 |
| 判斷 | 只按人氣 | 說明適配度 | 有試用、回退及維護考慮 |

通過標準：Context 和排錯至少基本通過，Skill 比較不得只依賴人氣。

## 所需材料

- `LH-WF-04` Context 超載恢復。
- `LH-WF-05` 四層排錯。
- `LH-WF-06` Skill 搜尋及評估。

## 證據邊界
