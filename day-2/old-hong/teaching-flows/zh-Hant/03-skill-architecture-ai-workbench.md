# 教學模組 03｜Skill 架構與個人 AI 工作台

建議時長：90 分鐘

## 對象與先備知識

- 對象：內容營運、部門主管、AI 推動者及已有重複成功流程的人。
- 先備：帶來兩個成功案例及一個失敗案例。

## 學習成果

1. 把已驗證工作拆成 Skill 的觸發、規則、資源和驗收。
2. 修復用途混合和規則衝突。
3. 畫出資訊、生產、數據、復盤四層工作台。
4. 建立一條可在四週內試用的 MVP 路線。

## 分鐘級流程

| 時間 | 教學活動 | 講師提示 | 學員產出 |
|---|---|---|---|
| 00–12 | 成功／失敗案例對照 | 不從空白文件開始 | 固定與可變部分 |
| 12–25 | 隱性判斷外顯 | 問停止、例外、拒絕和升級 | 判斷清單 |
| 25–38 | Skill 頂層設計 | 意圖 → 路由 → 專用流程 → 驗收 | 路由圖 |
| 38–48 | 規則與資源拆分 | 主層只留硬規則及路由 | Skill 骨架 |
| 48–60 | 工作台四層 | 情報、生產、數據、復盤 | 現況工作鏈 |
| 60–72 | MVP 選擇 | 只選一條高頻鏈路 | MVP 畫布 |
| 72–83 | 數據回流 | 總量、中位數、象限、原因假設 | 月度指標表 |
| 83–90 | 互評及 Exit Ticket | 另一組判斷能否落地 | 修改清單 |

## 講師示範

- 用成功案例抽出固定方法，不以生成空 Skill 作示範終點。
- 把一個混合多用途 Skill 改成清楚路由和按需參考。
- 用內容工作台展示發佈後數據如何回到下一輪規則。

## 學員練習

1. 從三個案例建立 Skill 規格。
2. 畫一張意圖路由圖。
3. 列出每日來源、每週交付和每月數據。
4. 選一條高頻工作做四週 MVP。

## 檢查問題

- 哪些判斷只有方法擁有人知道？
- 主 Skill 中哪部分應搬到參考或工具？
- 工作台在哪一步形成結果回流？
- MVP 成功後，哪項規則才值得升級？

## 課後作業

四週內完成一條工作台 MVP，每週記錄使用次數、節省時間、錯誤和修改。

## 評分量規

| 維度 | 未通過 | 基本通過 | 熟練 |
|---|---|---|---|
| Skill 證據 | 沒有成功案例 | 兩成功一失敗 | 案例能支持規則與例外 |
| 架構 | 所有內容在一層 | 有路由及資源拆分 | 意圖清楚且沒有衝突 |
| 工作台 | 只是工具清單 | 有四層工作鏈 | 一條鏈路真正閉環 |
| 復盤 | 只有數據 | 有原因假設 | 假設、測試及規則更新可追溯 |

通過標準：Skill 可由非作者理解，工作台 MVP 有單一使用者和量度指標。

## 所需材料

- `LH-WF-07`、`LH-WF-08`、`LH-WF-09`、`LH-WF-10`。
- Skill 規格、工作台 MVP 及月度復盤模板。

## 證據邊界

Skill 及工作台概念源自老洪課堂；四週 MVP 和教學量規屬實施設計。
