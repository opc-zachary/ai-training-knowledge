# 教学模组 02｜Context、Prompt 排错与 Skill 入门

建议时长：90 分钟

## 对象与先备知识

- 对象：需要处理长任务、排查 AI 输出或开始使用 Skill 的团队。
- 先备：能提供一个曾经答非所问的 Prompt 案例。

## 学习成果

1. 判断 Context 超载及隐藏背景污染。
2. 用四层排错定位主要根因。
3. 建立可在新窗口使用的交接摘要。
4. 搜寻和评估现成 Skill，而不只看人气。

## 分钟级流程

| 时间 | 教学活动 | 讲师提示 | 学员产出 |
|---|---|---|---|
| 00–10 | 长对话失准诊断 | 比较遗忘、混线及压缩症状 | 症状分类 |
| 10–22 | Context Brief | 区分事实、决定、假设、限制 | 一页交接摘要 |
| 22–38 | 四层排错讲解 | 目标、流程、格式、背景逐层检查 | 四层诊断表 |
| 38–52 | 失败案例修复 | 只允许修改一个主要层 | 修订 Prompt |
| 52–62 | Skill 定义 | 说明可重用方法与一般 Prompt 的差别 | 可封装候选 |
| 62–76 | 搜寻示范 | 任务、产出、工具三组关键词 | 三个候选 |
| 76–86 | 候选评估 | 适配、依赖、可读性、维护 | 比较表 |
| 86–90 | Exit Ticket | 问「这次失败真正属哪一层？」 | 根因一句话 |

## 讲师示范

- 把一段过长 Context 压缩成六栏交接摘要。
- 对一个答非所问案例逐层排错，不以「再专业一点」作修复。
- 查看候选 Skill 的实际规则和依赖，再与介绍页比较。

## 学员练习

1. 使用自己的失败 Prompt 填四层诊断。
2. 建立最小修订并在固定案例重跑。
3. 为一项工作搜寻三个 Skill 候选。
4. 作出采用、改造、借鉴或自建决定。

## 检查问题

- 哪些资讯是事实，哪些只是过去对话推测？
- 修改的是目标、流程、格式还是背景？
- 候选 Skill 会依赖什么工具或外部资料？
- 如果候选很热门但不符合交付物，应如何处理？

## 课后作业

提交一份 Context Brief、一份 Prompt 排错记录及一份三候选 Skill 评估表。

## 评分量规

| 维度 | 未通过 | 基本通过 | 熟练 |
|---|---|---|---|
| Context | 复制全部历史 | 有最小摘要 | 事实、决定、假设清楚分开 |
| 排错 | 同时重写所有内容 | 定位主要层 | 可重现并证明修订有效 |
| 搜寻 | 只找一个候选 | 比较三个候选 | 实际阅读规则与依赖 |
| 判断 | 只按人气 | 说明适配度 | 有试用、回退及维护考虑 |

通过标准：Context 和排错至少基本通过，Skill 比较不得只依赖人气。
