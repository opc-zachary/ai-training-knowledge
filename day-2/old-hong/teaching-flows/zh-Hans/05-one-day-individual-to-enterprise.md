# 一日课程｜由个人方法到企业落地

有效教学时间：360 分钟；另设午膳及两次短休息。

## 对象与先备知识

- 对象：企业管理者、部门骨干、内容营运、AI 推动者及解决方案团队。
- 先备：每组带来一项重复工作、一个失败 Prompt 和三个企业候选场景。

## 学习成果

1. 建立并隔离测试一个行业 Prompt。
2. 完成一个可重用 Skill 的顶层规格。
3. 画出个人或部门 AI 工作台 MVP。
4. 选择一个 FDE 试点并建立交付章程。

## 分钟级流程

| 时间 | 模组 | 核心活动 | 阶段产出 |
|---|---|---|---|
| 00–20 | 开场与基线 | 个人工作、AI 失败及企业场景盘点 | 现况基线 |
| 20–75 | Prompt 方法 | 六栏 Brief、人机共创、行业权重 | Prompt v01 |
| 75–95 | 隔离测试 | 新窗口及第二案例 | 测试差距 |
| 95–105 | 休息 | — | — |
| 105–145 | Context 与排错 | 四层诊断及最小修订 | Prompt v02 |
| 145–190 | Skill 设计 | 成功案例、隐性判断、路由与验收 | Skill 规格 |
| 190–250 | 午膳 | — | — |
| 250–295 | 工作台 MVP | 情报、生产、数据、复盘 | MVP 画布 |
| 295–330 | 数据回流 | 指标、象限、原因假设及规则 | 复盘表 |
| 330–340 | 休息 | — | — |
| 340–385 | 自动化选型 | 模板、工作流、Skill、Agent 比较 | 选型表 |
| 385–430 | FDE 试点 | 场景评分、边界、四阶段交付 | 试点章程 |
| 430–450 | Capstone 发表 | 每组讲述由个人方法到企业试点 | 完整方案 |

## 模组转场

- Prompt → Skill：一次成功要变成可重用方法，必须补案例、例外及验收。
- Skill → 工作台：单一能力要产生持续价值，必须接入上下游及结果回流。
- 工作台 → 企业：个人能用不代表全员会用，企业需要入口、责任和维护。
- 企业 → FDE：工具不能自行理解现场，必须有人连接工程和业务。

## 讲师示范

使用同一个「每月行业及内容洞察」案例贯穿全日：先做 Prompt，再封装 Skill、连入工作台，最后设计小团队试点。

## 学员练习

Capstone 必须包含：

1. 六栏问题定义。
2. Prompt v01／v02 及第二案例差距。
3. Skill 触发、输入、输出、规则和验收。
4. 工作台四层及一个数据回流。
5. 自动化选型理由。
6. FDE 试点基线、边界、期限、回退及四类验收。

## 检查问题

- 这项工作为何值得重复自动化？
- 哪些知识来自业务专家而不是模型？
- 非作者能否在干净 Context 完成？
- 个人工作台的结果如何改变下一轮规则？
- 为什么选这个试点而不是更大的核心流程？

## 课后作业

两周内完成 Prompt／Skill 试用；四周内完成工作台或 FDE 小试点的第一轮回读。

## 评分量规

| 维度 | 权重 | 通过证据 |
|---|---:|---|
| 问题及行业判断 | 20% | 六栏完整、三条专业判断 |
| Prompt 及测试 | 20% | 第二案例、新旧差距可追溯 |
| Skill 架构 | 20% | 路由、规则、资源、验收清楚 |
| 工作台闭环 | 20% | 资讯到复盘完整、有一项量度 |
| 企业试点 | 20% | 场景评分、回退及四类验收 |

通过标准：总分 70 分以上，且企业试点维度不得低于该项 60%。

## 所需材料

- 九条指定工作流。
- 八份可复制模板。
- 小组案例、计时器及成果发表表。

## 证据边界

一日结构是把老洪四段内容转成连续能力路线的教学设计，不代表原课堂以相同课时或活动授课。
