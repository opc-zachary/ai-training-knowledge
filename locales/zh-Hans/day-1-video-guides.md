### 时间线

| 时间 | 主题 | 重点理解 |
|---|---|---|
| 00:00–04:00 | 由聊天机器人到 Agent 浪潮 | 模型能力提升不等于 Agent；Agent 还需要任务拆解、工具及交付。 |
| 04:00–08:00 | 由「干活」变成「派活」 | 人的角色由直接操作转向定义、监督及验收。 |
| 08:00–10:00 | 三条业务学习主线 | 多模态内容、重复工作自动化、把经验变成提示词／Skill／流程。 |
| 10:00–14:00 | 对话、专用工具与 Agent | 对话产品回答问题；专用工具完成单一媒体任务；Agent 推进多步工作。 |
| 14:00–18:00 | 厂商、产品及模型层 | 同一公司有多个模型、介面及 Agent；工具名称不能代替模型名称。 |
| 18:00–22:00 | 多模态及影片模型 | 文字、图片及影片是不同能力；评估影片要看可用率及成本。 |
| 22:00–26:00 | 模型选择与中文品质 | 最新模型不一定最适合文案；视觉品质与中文字正确度也要分开测。 |
| 26:00–27:42 | 闭环 Agent | 真正价值是读取资料、处理、产出档案及验证，而非只回答一句。 |

### 核心架构

```text
业务目标
→ Agent／工作流
→ 模型
→ 工具、档案及连接器
→ 交付成果
→ 验收及读回
```

### 常见错误

- 未定义任务就问「哪个 AI 最好」。
- 把 App 名称当成模型能力。
- 只看一个精彩样本，不计算失败生成及人工修改。
- 把 Agent 的自主性误当成无限制权限。

### 练习

选一件真实工作，分别写出目标、交付、Agent 类型、模型能力、工具、权限及验收证据。

## 04｜品牌研究实操与报告交付

- 时长：00:19:09
- 模组：K02、K03
- 状态：`direct_course_mapping`

### 时间线

| 时间 | 主题 | 重点理解 |
|---|---|---|
| 00:00–04:00 | 工作区及提示词改进 | 一次任务的改善主要靠指令、背景及迭代，不是神秘的「训练」。 |
| 04:00–06:00 | 提示词库 | 把过去顾问工作的问题与方法固化，让团队重用。 |
| 06:00–08:00 | 利益相关者视角 | CEO、品牌总监、品牌经理及产品经理需要不同研究。 |
| 08:00–10:00 | 幻觉及报告结构 | 详细角色、要求及结构可减少随机性，但不能取代核证。 |
| 10:00–14:00 | 报告转 HTML | 清晰层级、表格及重点标示令长报告更易讲解。 |
| 14:00–19:09 | 协作文档及授权 | 连接器将结果写入协作平台；必须确认帐号、授权及目的地。 |

### 利益相关者对照

| 对象 | 决策 | 研究重点 |
|---|---|---|
| CEO／创办人 | 公司往哪里走 | 市场、增长、差异、风险 |
| 品牌总监 | 品牌如何发展 | 定位、年度叙事、产品组合、渠道 |
| 品牌经理 | 下一步做什么 | 竞品活动、受众反应、内容及执行 |
| 产品经理 | 改什么产品 | 使用场景、投诉、需求、功能及价格证据 |

### 验收

研究必须回答预定决策；重要数字有来源、日期及口径；HTML 不得用漂亮排版掩盖不确定性；协作文档必须在正确帐号及位置读回。

## 05｜研究方法、平台搜索及多模态过渡

- 时长：00:27:42
- 模组：K03、K04、K05
- 状态：`direct_course_mapping`

### 时间线

| 时间 | 主题 | 重点理解 |
|---|---|---|
| 00:00–04:00 | 研究到发布闭环 | 提示词产出研究，再转 HTML、部署或协作文档；每一层都要验收。 |
| 04:00–08:00 | 系统提示词与方法抽取 | 与 AI 讨论、修正假设，再把最终理解固化为可重用方法。 |
| 08:00–10:00 | 资料来源审查 | 不同报告的数据口径可能不同，要核对来源、期间及定义。 |
| 10:00–14:00 | 一般搜索的限制 | 封闭平台及电商资料未必能由公开搜索取得，方法要配合资料环境。 |
| 14:00–18:00 | 平台资料及大规模接口 | 小量可由可见页面整理；大规模历史资料可能需要授权供应商或 API。 |
| 18:00–20:00 | 研究方法分层 | 小问题、大型公开研究、平台采集及付费资料是不同层次。 |
| 20:00–24:00 | 语音转录及清理 | 转录是专门能力；要保留原始、清理、修订及不确定段落。 |
| 24:00–27:42 | 多模态及一人市场部 | 文字、图片、影片、社交内容及 PR 可组成一个人管理的内容系统。 |

### 四级研究方法

| 级别 | 适用情况 | 主要风险 |
|---|---|---|
| 模型直接回答 | 低风险入门问题 | 过时、无来源 |
| 深度公开研究 | 公开资料能回答 | 口径冲突 |
| 平台可见资料整理 | 需要帖子／评论 | 样本不完整、平台限制 |
| 授权资料供应商／API | 大规模或历史资料 | 成本、来源及使用权 |

### 可信度六问

谁发布？什么期间？涵盖哪个市场？计算什么？属于实际、抽样或估算？能否回到原始资料抽查？

## 06｜文字品质、作者调性及商业内容

- 影片：`DJI_20260829161417_0016_D`
- 时长：00:20:30
- 模组：K05
- 状态：`direct_course_mapping`

### 时间线

| 时间 | 主题 | 重点理解 |
|---|---|---|
| 00:00–04:00 | AI 商业内容观察 | 好看不等于有洞察；AI 承诺要连接真实使用场景及可信机制。 |
| 04:00–08:00 | 电商内容及模型差异 | 同一 Brief 在不同模型会有不同语气、节奏及判断。 |
| 08:00–12:00 | 短指令与 AI 味 | 缺少受众、冲突、品牌立场及证据时，模型会填入通用套路。 |
| 12:00–16:00 | 作者稳定系统 | 分析作者站位、关注、价值排序、判断方式及读者关系。 |
| 16:00–20:00 | 新主题测试及 PR 问题 | 保留判断内核但改变结构；避免空泛宏大、平均乐观及企业套话。 |
| 20:00–20:30 | 固化方法 | 把已验证的作者规则放回工作环境重用。 |

### 作者调性六层

1. 观察位置。
2. 持续注意的矛盾。
3. 价值排序。
4. 由证据到结论的方法。
5. 与读者的关系。
6. 情绪及表达边界。

成功标准不是「用了同样口头禅」，而是换掉句式后仍能认出作者的角度及判断。

## 07｜图片控制及电商视觉生产

- 影片：`DJI_20260829164130_0017_D`
- 时长：00:27:41
- 模组：K06、K07
- 状态：`direct_course_mapping`

### 时间线

| 时间 | 主题 | 重点理解 |
|---|---|---|
| 00:00–04:00 | 由生成到可交付 | 生图容易，生产级控制困难；模型品质及参考图会大幅影响结果。 |
| 04:00–08:00 | 产品适配及多图拼合 | 不同输入分别提供构图、人物、产品或场景；推断出的价钱及声明必须核证。 |
| 08:00–12:00 | 换装、局部修改及反推 | 改一个元素并明确保留其他内容；同时改动越少越稳定。 |
| 12:00–16:00 | 品类变数及创意味道 | 服装重人物与材质；美妆重质感；创意海报重概念及艺术指导。 |
| 16:00–20:00 | 三种控制法与工具取舍 | 垫图、拼图、反推；工具要按精准度、成本、复杂度及重用选择。 |
| 20:00–24:00 | 厂商堆叠与详情页流程 | 产品 Brief 需转成卖点、页面次序、视觉证据及文案。 |
| 24:00–27:41 | 批量生成及自审 | Agent 规划五主图、十详情页、逐张生成、检查及重做。 |

### 图片控制四法

1. 参考图：借用层级、光线、密度及气氛。
2. 多图拼合：为每张输入指定角色。
3. 局部修改：圈定改动并保留其他内容。
4. 视觉反推：把构图、文字、颜色及效果转成结构化规格。

### 验收

产品形状及颜色准确；画面能证明讯息；中文字逐字正确；没有虚构价钱、奖项、认证或功效；人物与产品互动合理；整套图一致但不重复。

## 08｜Skill 批量生产及模型路由

- 影片：`DJI_20260829170913_0018_D`
- 时长：00:02:22
- 模组：K07
- 状态：`direct_course_mapping`

同一 Skill 可以让产品图与参考图产生一套互相连接的主图及详情页。Agent 不只读取当前提示词，也会参考前面输出，维持风格连续。

### 模型路由

```text
Agent 介面
→ Skill
→ 任务计划及提示词
→ 内置或外部模型
→ 批量输出
→ Agent 自审及重做
```

选择外部模型时要知道供应者、模型、成本、资料路径、失败处理及替代方案。不能因为某个中转站「什么都有」就当成可控的生产环境。

## 10｜影片工作台、数据分析及课程总结

- 模组：K08、K09、K10
- 状态：`verified_video`

### 时间线

| 时间 | 主题 | 重点理解 |
|---|---|---|
| 00:00–08:00 | 分镜到影片工作台 | 先做人物、三视图、场景及镜头，再生成短片段，减少长片抽卡。 |
| 08:00–12:00 | 转入数据及清洗 | 数据分析要先检查空值、错误、类型及栏位关系。 |
| 12:00–16:00 | 专家流程及销售仪表板 | 由交易列产生销售、毛利、区域、渠道、品类、销售员及月度视图。 |
| 16:00–20:00 | 变化问题及互动 HTML | 不只看总数，要找出谁、什么产品或地区发生变化。 |
| 20:00–22:00 | 对帐及交付 | 要求系统再检查，并由来源抽样核对重要结果。 |
| 22:00–24:45 | 课程总结 | 模型、Agent、内容、Skill、数据及 QA 是同一条业务学习主线。 |

### 数据闭环

```text
原始档
→ 结构及质量检查
→ 清洗记录
→ 指标定义
→ 趋势及异常分析
→ 仪表板
→ 来源对帐
→ 决策及后续
```

完成不等于「成功生成 HTML」，而是所有 KPI 有定义、清洗有记录、图表与同一干净资料一致、总数可由来源重算、目的地能读回。
