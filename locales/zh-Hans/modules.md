# K00–K10 模组手册

## K00｜创新及学习生态

### 目标

把 AI 试验变成有拥有人、审查者及采用路径的组织能力。

### 流程

1. 列出值得解决的业务问题。
2. 为每个问题指定业务拥有人。
3. 配对领域专家、AI 操作者及审查者。
4. 建立有边界的试验环境。
5. 定义由原型升级为正式流程的条件。
6. 定期展示成果、证据及失败。
7. 把可重用方法写成 Skill、模板或 SOP。

### 验收

一个试验必须有真实问题、成果证据、审查、采用路径及维护者，而不是只在 Demo 中看起来厉害。

---

## K01｜模型、Agent 与工具框架

### 五层架构

| 层次 | 问题 |
|---|---|
| 业务目标 | 需要什么决策或交付？ |
| Agent／流程 | 谁负责拆解及推进？ |
| 模型 | 需要什么推理、语言或媒体能力？ |
| 工具 | 要读写哪些档案、API 或应用？ |
| 验证 | 如何证明内容及交付正确？ |

### 选择方法

在同一真实 Brief 下测试候选模型，比较品质、延迟、成本、一致性及修改时间。记录介面及底层模型，不用品牌印象代替测试。

---

## K02｜有边界的 Agent 工作空间

### 最小规格

```text
Project／客户：
目标：
允许资料夹：
允许工具：
允许外部目的地：
禁止行为：
输出命名及版本：
批准点：
读回方式：
```

### 验收

没有接触无关档案；每个输出有 Project 及版本；外部身份及目的地清楚；最终物件能在目的地读回。

## K03｜有证据的品牌及行业研究

### 输入

研究对象、决策者、决策、地域、期间、产品线、竞品选择逻辑、来源类别及交付格式。

### 流程

1. 把决策转成研究问题。
2. 先设计证据计划，再开始搜索。
3. 每个重要主张保存来源、发布者、日期及范围。
4. 分开事实、解读及建议。
5. 处理数据口径冲突。
6. 分析品牌基因、演进、产品组合、沟通、竞争及风险。
7. 执行矛盾及缺失证据审查。

### 验收

审查者能追溯重要结论、理解数字冲突及看到建议如何由证据推导。

## K04｜平台资料及消费者洞察

### 流程

定义研究问题及样本 → 记录可见内容 → 去重及标准化 → 分类场景、痛点、反对及期望 → 分开帖子与评论 → 比较热门及普通内容 → 返回原帖抽查 → 清楚写出样本限制。

### 洞察格式

| 证据 | 解读 | 业务含义 | 信心 |
|---|---|---|---|
| 重复投诉 | 未满足期望 | 产品／服务改善 |  |
| 重复用语 | 受众语言 | 文案／搜索词 |  |
| 重复场景 | 使用情境 | 创意／渠道计划 |  |

### 常见失败

把 Like 当成销售；只分析爆文；忽略负面评论；把小样本当成市场份额。

## K05｜作者调性及 PR 系统

### 流程

1. 收集不同主题的代表作。
2. 找出跨文章稳定规律。
3. 排除平台及单次任务造成的假规律。
4. 定义站位、注意力、价值排序、判断、读者关系及情绪边界。
5. 分开「必须保持」与「可以变化」。
6. 用新题目测试。
7. 分别检查作者身份及内容原创性。

### 验收

删除相似句式后，角度与判断仍像作者；更换文章结构后，身份仍成立。

---

## K06｜可控制的图片生成

### 四种方法

参考图引导、多图拼合、局部修改、视觉反推。

### 流程

定义商业角色 → 写出「遮住文字后画面证明什么」→ 为每张参考图指定角色 → 列出不能改的产品事实 → 限制同时改动 → 生成候选 → 核对产品、人物、文字、声明及构图 → 失败则重生。

### 验收

产品准确、讯息有视觉证据、中文字正确、没有虚构声明、人物合理、比例符合渠道。

---

## K07｜可重用电商视觉 Skill

### 流程

1. 审核产品、事实、品牌及参考输入。
2. 建立消费者焦虑、期望、场景、反对及证据地图。
3. 定义视觉 DNA 及颜色规则。
4. 规划五张主图及十张详情页角色。
5. 每张写 Picture-solo statement。
6. 先审整套计划，再生成。
7. 逐档及整套验证。

### 硬性检查

五主图至少四种主视觉；十详情页至少七种主视觉；至少四页不是完整包装主导；相邻页不重复同一证据形式；所有声明有来源。

## K08｜AI 影片生产

### 流程

Brief → 人物设定 → 场景设定 → 镜头表 → 参考帧／分镜 → 短片生成 → 逐帧审查 → 剪辑 → 声音与字幕 → 最终输出检查。

### 必查问题

人物、手眼口、产品、背景物件、光影、镜头与主体运动、文字、口型及叙事功能。

### 成本

有效成本＝总生成支出 ÷ 最终保留的可用秒数。失败片段及人工修正时间都要计算。

---

## K09｜业务数据分析

### 流程

保存原档 → 资料字典 → 质量剖析 → 清洗记录 → KPI 定义 → 总量与分布 → 趋势及异常 → 图表 → 对帐 → 决策。

### 必备交付

来源 manifest、数据字典、质量报告、清洗记录、指标定义、分析、仪表板、对帐证据及决策摘要。

### 验收

同一输入可重现；KPI 有公式及范围；排除资料有披露；仪表板总数可与来源对帐；建议与证据强度匹配。

## K10｜QA、证据及交付

### 四道闸门

| 闸门 | 问题 |
|---|---|
| 输入 | 是否使用正确 Project、客户、来源及版本？ |
| 过程 | 方法、模型、工具及修改是否有记录？ |
| 输出 | 内容及格式是否符合要求？ |
| 目的地 | 实际交付物能否在正确位置独立读回？ |

### 结果标签

- `VERIFIED_COMPLETE`：目的地及证据都正确。
- `LOCAL_COMPLETE_EXTERNAL_PENDING`：本地完成，外部尚待执行。
- `OUTCOME_UNCERTAIN`：可能已写入，必须先对帐。
- `BLOCKED`：缺少必要来源、身份、能力或授权。

生成成功、Commit、Push、API accepted 或 Dashboard 显示绿色都只是中间证据，不能单独代表完成。
