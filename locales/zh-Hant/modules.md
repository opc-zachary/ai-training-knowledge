# K00–K10 模組手冊

## K00｜創新及學習生態

### 目標

把 AI 試驗變成有擁有人、審查者及採用路徑的組織能力。

### 流程

1. 列出值得解決的業務問題。
2. 為每個問題指定業務擁有人。
3. 配對領域專家、AI 操作者及審查者。
4. 建立有邊界的試驗環境。
5. 定義由原型升級為正式流程的條件。
6. 定期展示成果、證據及失敗。
7. 把可重用方法寫成 Skill、模板或 SOP。

### 驗收

一個試驗必須有真實問題、成果證據、審查、採用路徑及維護者，而不是只在 Demo 中看起來厲害。

---

## K01｜模型、Agent 與工具框架

### 五層架構

| 層次 | 問題 |
|---|---|
| 業務目標 | 需要甚麼決策或交付？ |
| Agent／流程 | 誰負責拆解及推進？ |
| 模型 | 需要甚麼推理、語言或媒體能力？ |
| 工具 | 要讀寫哪些檔案、API 或應用？ |
| 驗證 | 如何證明內容及交付正確？ |

### 選擇方法

在同一真實 Brief 下測試候選模型，比較品質、延遲、成本、一致性及修改時間。記錄介面及底層模型，不用品牌印象代替測試。

---

## K02｜有邊界的 Agent 工作空間

### 最小規格

```text
Project／客戶：
目標：
允許資料夾：
允許工具：
允許外部目的地：
禁止行為：
輸出命名及版本：
批准點：
讀回方式：
```

### 驗收

沒有接觸無關檔案；每個輸出有 Project 及版本；外部身份及目的地清楚；最終物件能在目的地讀回。

## K03｜有證據的品牌及行業研究

### 輸入

研究對象、決策者、決策、地域、期間、產品線、競品選擇邏輯、來源類別及交付格式。

### 流程

1. 把決策轉成研究問題。
2. 先設計證據計劃，再開始搜索。
3. 每個重要主張保存來源、發布者、日期及範圍。
4. 分開事實、解讀及建議。
5. 處理數據口徑衝突。
6. 分析品牌基因、演進、產品組合、溝通、競爭及風險。
7. 執行矛盾及缺失證據審查。

### 驗收

審查者能追溯重要結論、理解數字衝突及看到建議如何由證據推導。

## K04｜平台資料及消費者洞察

### 流程

定義研究問題及樣本 → 記錄可見內容 → 去重及標準化 → 分類場景、痛點、反對及期望 → 分開帖子與評論 → 比較熱門及普通內容 → 返回原帖抽查 → 清楚寫出樣本限制。

### 洞察格式

| 證據 | 解讀 | 業務含義 | 信心 |
|---|---|---|---|
| 重複投訴 | 未滿足期望 | 產品／服務改善 |  |
| 重複用語 | 受眾語言 | 文案／搜索詞 |  |
| 重複場景 | 使用情境 | 創意／渠道計劃 |  |

### 常見失敗

把 Like 當成銷售；只分析爆文；忽略負面評論；把小樣本當成市場份額。

## K05｜作者調性及 PR 系統

### 流程

1. 收集不同主題的代表作。
2. 找出跨文章穩定規律。
3. 排除平台及單次任務造成的假規律。
4. 定義站位、注意力、價值排序、判斷、讀者關係及情緒邊界。
5. 分開「必須保持」與「可以變化」。
6. 用新題目測試。
7. 分別檢查作者身份及內容原創性。

### 驗收

刪除相似句式後，角度與判斷仍像作者；更換文章結構後，身份仍成立。

---

## K06｜可控制的圖片生成

### 四種方法

參考圖引導、多圖拼合、局部修改、視覺反推。

### 流程

定義商業角色 → 寫出「遮住文字後畫面證明甚麼」→ 為每張參考圖指定角色 → 列出不能改的產品事實 → 限制同時改動 → 生成候選 → 核對產品、人物、文字、聲明及構圖 → 失敗則重生。

### 驗收

產品準確、訊息有視覺證據、中文字正確、沒有虛構聲明、人物合理、比例符合渠道。

---

## K07｜可重用電商視覺 Skill

### 流程

1. 審核產品、事實、品牌及參考輸入。
2. 建立消費者焦慮、期望、場景、反對及證據地圖。
3. 定義視覺 DNA 及顏色規則。
4. 規劃五張主圖及十張詳情頁角色。
5. 每張寫 Picture-solo statement。
6. 先審整套計劃，再生成。
7. 逐檔及整套驗證。

### 硬性檢查

五主圖至少四種主視覺；十詳情頁至少七種主視覺；至少四頁不是完整包裝主導；相鄰頁不重複同一證據形式；所有聲明有來源。

## K08｜AI 影片生產

### 流程

Brief → 人物設定 → 場景設定 → 鏡頭表 → 參考幀／分鏡 → 短片生成 → 逐幀審查 → 剪輯 → 聲音與字幕 → 最終輸出檢查。

### 必查問題

人物、手眼口、產品、背景物件、光影、鏡頭與主體運動、文字、口型及敘事功能。

### 成本

有效成本＝總生成支出 ÷ 最終保留的可用秒數。失敗片段及人工修正時間都要計算。

---

## K09｜業務數據分析

### 流程

保存原檔 → 資料字典 → 質量剖析 → 清洗記錄 → KPI 定義 → 總量與分布 → 趨勢及異常 → 圖表 → 對帳 → 決策。

### 必備交付

來源 manifest、數據字典、質量報告、清洗記錄、指標定義、分析、儀表板、對帳證據及決策摘要。

### 驗收

同一輸入可重現；KPI 有公式及範圍；排除資料有披露；儀表板總數可與來源對帳；建議與證據強度匹配。

---

## K10｜QA、證據及交付

### 四道閘門

| 閘門 | 問題 |
|---|---|
| 輸入 | 是否使用正確 Project、客戶、來源及版本？ |
| 過程 | 方法、模型、工具及修改是否有記錄？ |
| 輸出 | 內容及格式是否符合要求？ |
| 目的地 | 實際交付物能否在正確位置獨立讀回？ |

### 結果標籤

- `VERIFIED_COMPLETE`：目的地及證據都正確。
- `LOCAL_COMPLETE_EXTERNAL_PENDING`：本地完成，外部尚待執行。
- `OUTCOME_UNCERTAIN`：可能已寫入，必須先對帳。
- `BLOCKED`：缺少必要來源、身份、能力或授權。

生成成功、Commit、Push、API accepted 或 Dashboard 顯示綠色都只是中間證據，不能單獨代表完成。
