### 核心架構

```text
業務目標
→ Agent／工作流
→ 模型
→ 工具、檔案及連接器
→ 交付成果
→ 驗收及讀回
```

### 常見錯誤

- 未定義任務就問「哪個 AI 最好」。
- 把 App 名稱當成模型能力。
- 只看一個精彩樣本，不計算失敗生成及人工修改。
- 把 Agent 的自主性誤當成無限制權限。

### 練習

選一件真實工作，分別寫出目標、交付、Agent 類型、模型能力、工具、權限及驗收證據。

| 級別 | 適用情況 | 主要風險 |

| 04:00–08:00 | 電商內容及模型差異 | 同一 Brief 在不同模型會有不同語氣、節奏及判斷。 |
| 08:00–12:00 | 短指令與 AI 味 | 缺少受眾、衝突、品牌立場及證據時，模型會填入通用套路。 |

### 作者調性六層

1. 觀察位置。
2. 持續注意的矛盾。
3. 價值排序。
4. 由證據到結論的方法。
5. 與讀者的關係。
6. 情緒及表達邊界。

成功標準不是「用了同樣口頭禪」，而是換掉句式後仍能認出作者的角度及判斷。

## 07｜圖片控制及電商視覺生產

- 影片：`DJI_20260829164130_0017_D`
- 時長：00:27:41
- 模組：K06、K07
- 狀態：`direct_course_mapping`

### 時間線

| 時間 | 主題 | 重點理解 |
|---|---|---|
| 00:00–04:00 | 由生成到可交付 | 生圖容易，生產級控制困難；模型品質及參考圖會大幅影響結果。 |
| 04:00–08:00 | 產品適配及多圖拼合 | 不同輸入分別提供構圖、人物、產品或場景；推斷出的價錢及聲明必須核證。 |
| 08:00–12:00 | 換裝、局部修改及反推 | 改一個元素並明確保留其他內容；同時改動越少越穩定。 |
| 12:00–16:00 | 品類變數及創意味道 | 服裝重人物與材質；美妝重質感；創意海報重概念及藝術指導。 |
| 16:00–20:00 | 三種控制法與工具取捨 | 墊圖、拼圖、反推；工具要按精準度、成本、複雜度及重用選擇。 |
| 20:00–24:00 | 廠商堆疊與詳情頁流程 | 產品 Brief 需轉成賣點、頁面次序、視覺證據及文案。 |
| 24:00–27:41 | 批量生成及自審 | Agent 規劃五主圖、十詳情頁、逐張生成、檢查及重做。 |

### 圖片控制四法

1. 參考圖：借用層級、光線、密度及氣氛。
2. 多圖拼合：為每張輸入指定角色。
3. 局部修改：圈定改動並保留其他內容。
4. 視覺反推：把構圖、文字、顏色及效果轉成結構化規格。

### 驗收

產品形狀及顏色準確；畫面能證明訊息；中文字逐字正確；沒有虛構價錢、獎項、認證或功效；人物與產品互動合理；整套圖一致但不重複。

## 08｜Skill 批量生產及模型路由

- 影片：`DJI_20260829170913_0018_D`
- 時長：00:02:22
- 模組：K07
- 狀態：`direct_course_mapping`

同一 Skill 可以讓產品圖與參考圖產生一套互相連接的主圖及詳情頁。Agent 不只讀取當前提示詞，也會參考前面輸出，維持風格連續。

### 模型路由

```text
Agent 介面
→ Skill
→ 任務計劃及提示詞
→ 內置或外部模型
→ 批量輸出
→ Agent 自審及重做
```

選擇外部模型時要知道供應者、模型、成本、資料路徑、失敗處理及替代方案。不能因為某個中轉站「甚麼都有」就當成可控的生產環境。

| 12:00–16:00 | 專家流程及銷售儀表板 | 由交易列產生銷售、毛利、區域、渠道、品類、銷售員及月度視圖。 |

### 數據閉環

```text
原始檔
→ 結構及質量檢查
→ 清洗記錄
→ 指標定義
→ 趨勢及異常分析
→ 儀表板
→ 來源對帳
→ 決策及後續
```

完成不等於「成功生成 HTML」，而是所有 KPI 有定義、清洗有記錄、圖表與同一乾淨資料一致、總數可由來源重算、目的地能讀回。
